## 자산군별 상세 현황

### 주식 (완료)
- **수집**: DART Open API(`src/collectors/dart_collector.py`) — 공시 원문까지 fetch 가능
- **뉴스**: 정부기관(금융위 FSC) RSS(`news_collector.py`) → 태거가 자산군 자동 분류
- **저장**: `stock_disclosures`, `stock_news` 테이블
- **키워드**: TF-IDF 1차 필터링 + LLM(OpenAI) 2차 정제
- **리포트**: 일/주/월/연 보고서에 공시+뉴스 통합 표시

### 채권 (완료)
- **수집**: 한국은행 ECOS Open API(`ecos_collector.py`) — 기준금리(`base_rate`), 코스피/코스닥/원달러환율(아래 참고) 프리셋 등록. 국고채 3년물 등은 통계코드 미확정으로 보류 중
- **뉴스**: 주식과 동일한 FSC RSS 파이프라인에서 채권 관련 항목 자동 분류
- **저장**: `bond_indicators`(시계열, ECOS/FRED 공용 — `asset_class` 컬럼으로 구분)
- **리포트**: "주요 금리·지수 지표" 섹션에 최근값 + 기간 중 변화 표시

### 해외 지수 — 나스닥/S&P500 (오늘 완료)
- **수집**: FRED(세인트루이스 연방준비은행) Open API(`fred_collector.py`) — `NASDAQCOM`/`SP500` 시리즈
- **CLI**: `scripts/collect_fred.py` (`--days`, `--indicators`), `bond_indicators` 테이블을 그대로 재사용(저장 로직 공유)
- **자산군 분리**: `bond_indicators`에 `asset_class` 컬럼 추가(ECOS=bond/FRED=stock 구분) — 이전엔 컬럼이 없어 채권/주식 리포트에 서로 데이터가 섞일 수 있었던 잠재 버그를 함께 수정
- **리포트**: `asset_class="stock"` 리포트에도 지표 섹션·차트가 표시되도록 게이트 확장, 채권/주식 리포트가 서로의 지표를 노출하지 않음을 테스트로 검증
- **스케줄러**: 4개 파이프라인(일/주/월/연) 전체에 통합, 실패해도 나머지 단계 진행
- **테스트**: 수집기(에러/파싱/휴장일 스킵/미지정 시 전체 조회) 6건, 저장 asset_class 보존 1건, 조회 필터링 1건, 리포트 분리 검증 1건, 스케줄러 통합 1건 신규 작성, 전체 통과 확인
- **⚠️ 사용자 진행 필요**: `FRED_API_KEY` 발급 — https://fred.stlouisfed.org 회원가입 후 My Account → API Keys에서 무료/즉시 발급 → `.env`의 `FRED_API_KEY` placeholder 교체 → `python -m scripts.collect_fred --days 30`로 검증

### 국내 지수 — 코스피/코스닥/원달러환율 (오늘 완료)
- **수집**: 한국은행 ECOS Open API, `ecos_collector.py`의 `INDICATOR_PRESETS`에 `kospi`/`kosdaq`/`usd_krw` 3개 프리셋 등록
- **stat_code 검증 과정**: ECOS 통계코드검색 엑셀 내려받기는 항목코드(item_code1)만 제공하고 상위 통계표코드(stat_code)가 없어서, 신규 작성한 `scripts/lookup_ecos_table.py`(ECOS StatisticTableList API 조회)를 사용자가 로컬에서 직접 실행해 확인 — 코스피/코스닥 = `802Y001`("1.5.1.1 주식시장(일)"), 원달러환율 = `731Y001`("3.1.1.1 주요국 통화의 대원화환율"). 추측 없이 실제 API 응답으로 검증함
- **자산군**: 코스피/코스닥 = `asset_class="stock"`, 원달러환율 = `asset_class="bond"`
- **테스트**: 3개 프리셋 파싱/asset_class 확인 2건 + 아래 버그의 저장 계층 회귀 테스트 1건 신규 작성, 전체 통과 확인
- **⚠️ 실사용 중 발견하고 수정한 버그 (1)**: 등록 직후 `python -m scripts.collect_bond`를 실사용해보니 코스피/코스닥이 같은 stat_code(802Y001)를 공유하는데 `indicator_code` 컬럼엔 stat_code만 저장해서 `(indicator_code, date)` DB 유니크 제약에 충돌 → `IntegrityError`로 전체 커밋이 롤백됨(부분 저장 없이 깔끔하게 실패). `indicator_code`를 `stat_code_item_code1` 조합으로 저장하도록 수정해 해결. 이 수정 전에 쌓인 `기준금리`(base_rate) 기존 행은 옛 코드(`722Y001`)를 그대로 갖고 있어, 리포트에 일시적으로 별도 시리즈 두 줄로 보일 수 있음(기능적 문제는 아님, `docs/TODO.md` 참고)
- **⚠️ 실사용 중 발견하고 수정한 버그 (2)**: 위 수정 후 실제로 리포트를 생성해보니 "KOSPI지수: 5593.561980.01.04=100 (...)"처럼 값·단위가 깨져 보임. ECOS가 코스피/코스닥 UNIT_NAME으로 실제 단위 대신 "1980.01.04=100"(기준시점 설명)을 내려주는데 이를 그대로 저장했기 때문. 항상 프리셋에 지정한 단위("pt")를 쓰도록 수정하고, `save_bond_indicators()`도 단위가 달라지면 기존 행을 자동 정정하도록 개선(수동 정리 불필요)

- **리포트**: "법령·규제 개정" 섹션 추가. 링크 대신 법령상세링크(HTML) 페이지에서 발췌한 개정이유 원문을 LLM으로 3~4줄 요약해 표시 (아래 "리포트 가독성 개선" 참고)

- **발견 후 수정한 버그**: "은행법"으로 검색하면 은행법 본법뿐 아니라 은행법 시행령/시행규칙 등 연관 법령까지 함께 반환되는데(실제로 6건 중 5건이 이 경우), 초기 코드는 제목에 검색어를 그대로 써서 전부 "은행법 개정"으로 표시되는 문제가 있었음 → 응답의 실제 `법령명한글` 필드를 쓰도록 수정, 자산군 매핑은 검색어 기준을 유지
- **⚠️ 정확도 한계 (남은 부분)**: 이 API의 법령 목록 조회는 법령명 검색 시 보통 "현재 시행중인 버전"만 반환하므로, 과거 개정 이력 전체가 아니라 "조회 시점 기준 가장 최근 개정이 지정 기간 안에 있었는지"만 감지하는 방식이다.
- **✅ 개정이유 추출 정확도 문제 라이브 검증 후 수정 (2026-08-01)**: 실제 LAW_API_KEY로 365일 조회(15건) 결과 개정이유 추출 성공률이 0/15였음. 원인 분석 결과, 법령상세링크 URL을 그대로 요청하면 실제 내용이 아니라 `<iframe>`으로 본문 페이지를 감싼 래퍼 HTML만 반환되고(예전 코드는 이 래퍼에서 바로 찾으려 해서 실패), 심지어 그 iframe이 가리키는 본문 페이지(lsInfoP.do)에도 "제·개정이유"는 없고 조문 본문만 있음 — 해당 텍스트는 별도 엔드포인트(`lsRvsDocInfoR.do?lsRvsGubun=Rsn`)에서만 내려온다는 것을 확인. `law_collector.py`의 `_fetch_reason_excerpt()`를 2단계 요청(래퍼에서 lsiSeq/chrClsCd 추출 → 해당 엔드포인트 재요청) 방식으로 재작성해 재검증 결과 15/15건 모두 추출 성공으로 개선.

## 리포트 가독성 개선 (오늘 완료)

사용자가 첫 리포트 결과물을 보고 요청한 개선 사항 3가지 반영:

- **"주요 공시·뉴스"/"법령·규제 개정" 링크 제거 + LLM 요약**: `src/analysis/summarizer.py` 신규. 문서/법령 원문을 배치 LLM 호출로 각각 2~4줄 요약해서 링크 대신 표시. LLM 호출 실패(키 미설정 등) 시 예외 없이 원문 일부로 조용히 대체 — 리포트 생성이 이 기능 때문에 멈추지 않음
- **`--days`/`--period-type` 불일치 버그 수정**: `--days 90 --period-type`(기본 weekly)처럼 실행하면 "주간 리포트"라는 제목인데 실제론 90일치가 들어가는 문제가 있었음 → `--days` 생략 시 `--period-type`에 맞는 표준 기간(daily=1/weekly=7/monthly=30/yearly=365) 자동 적용, 명시적으로 다르게 주면 안내 메시지 출력
- **주요 지수 추가**: 나스닥/S&P500(FRED), 코스피/코스닥/원달러환율(ECOS) 전부 연동 완료 — 위 "해외 지수"/"국내 지수" 항목 참고
- **⚠️ 실사용 중 발견하고 수정한 버그: "주요 공시·뉴스" 요약이 안 됨**: 법령 요약은 잘 되는데 공시·뉴스는 여전히 링크 없이 원문 일부만 잘려 나오는 문제 발견. 원인은 리포트에 표시되는 문서 30건을 한 번의 LLM 호출로 요약하려니 응답이 `max_tokens`에서 잘려 JSON 파싱이 통째로 실패하고(법령은 5건 이하라 문제 없었음) 전부 원문 truncate로 대체됐기 때문. `summarize_documents()`가 6건씩 나눠 여러 번 호출하도록 수정(한 배치가 실패해도 그 배치만 대체되고 나머지는 정상 요약), 응답 키도 원본 URL 대신 짧은 인덱스로 바꿔 안정성을 높이고 `max_tokens`도 2000 → 4096으로 상향
- **⚠️ 사용자 피드백으로 재개선 (2026-07-31)**: 공시/뉴스 30건이 각각 개별 요약 문단으로 나열되니 너무 길다는 피드백 → `summarizer.py`에 `summarize_group()` 신규 추가(여러 원문을 한 번에 받아 개별 나열 없이 종합 요약 하나만 생성, 최대 20건까지만 입력해 `max_tokens` 초과 방지). `report_generator.py`에서 표시 문서를 `content_type`(공시/뉴스/정책/공지)별로 묶어 그룹당 종합 요약 1개씩만 생성하도록 변경 — 이제 "공시 (N건)"/"뉴스 (N건)" 처럼 그룹별 요약만 표시되고, 개별 문서 제목·회사명 등은 더 이상 리포트에 노출되지 않음
- **⚠️ 사용자 피드백으로 재개선 (2026-08-01)**: (1) 격자 합성 차트가 산만하고 기준금리 그래프가 누락됨 → `generate_bond_charts()`가 지표별 개별 PNG를 생성하고 템플릿이 3열 `<table>`로 배치, 단일 데이터포인트 지표도 이제 포함됨. (2) 뉴스/공시 종합 요약이 `{"1": "..."}` 또는 `1: "..."` 형태로 그대로 노출됨 → `summarizer.py`에 `_strip_json_wrapper()` 추가해 순수 텍스트로 정리. (3) 문서 목록에 `--exclude-pattern`/`--only-enriched` 필터 미적용 → `src/common/document_filter.py`로 필터 로직을 공통화해 `report_generator.py`에도 적용(아래 "알려진 이슈" 항목 해결). (4) 그룹 요약으로 개별 문서 제목·링크가 사라진 트레이드오프 → `document_groups`에 `titles` 리스트를 추가하고 템플릿에서 `<details>` 접이식 목록으로 표시. 부수적으로 `bond_indicators`의 기준금리 옛 형식(`indicator_code='722Y001'`, 단위 "연%") 잔존 행 12건을 재수집 후 삭제해 정리.

## 배포 — 완료 (2026-08-01)

- **이메일 자동발송**: `src/reports/emailer.py` 신규 — Markdown 리포트를 HTML 이메일로 변환(`markdown` 라이브러리, 원본 HTML `<table>`/`<img>`/`<details>`도 그대로 통과)하고, 로컬 이미지(`charts/*.png`)는 상대경로라 이메일 클라이언트가 못 불러오므로 Content-ID 인라인 첨부(cid:)로 변환해 삽입. `scripts/send_report_email.py`로 수동 발송 가능(`--to` 또는 `.env`의 `REPORT_EMAIL_TO`), `src/scheduler/jobs.py`의 4개 파이프라인에도 `_maybe_email_report()`로 연결해 SMTP_HOST/REPORT_EMAIL_TO가 모두 설정된 경우에만 자동 발송(미설정 시 조용히 스킵 — 기존 사용자 파이프라인 깨지지 않음). STARTTLS는 서버가 지원할 때만 조건부 호출(`has_extn`)하도록 구현. 테스트 22건(모킹 기반, MIME 조립/파싱 라운드트립 포함) 전체 통과.
  - **⚠️ 라이브 SMTP 테스트 한계**: Python 내장 `smtpd.DebuggingServer`로 로컬 더미 서버를 띄워 실제 네트워크 E2E를 시도했으나, 이 샌드박스(Windows + 서브프로세스)에서 asyncore 이벤트 루프가 안정적으로 연결을 처리하지 못해 완전한 라이브 검증은 못함(TCP 포트는 열리지만 DATA 단계에서 타임아웃). 실제 SMTP 서버(Gmail 등) 자격증명으로 사용자가 직접 1회 발송 테스트 권장.
- **웹 대시보드**: `src/web/dashboard.py`(Flask) 신규 — `reports` 테이블의 저장된 리포트 목록을 보여주고, 클릭하면 Markdown을 HTML로 렌더링해서 표시. 차트 이미지는 `/charts/<파일명>` 라우트로 정적 서빙(리포트 안의 상대경로 `charts/파일명.png`를 절대경로로 치환). `scripts/run_dashboard.py --port`로 실행. requirements.txt에 `flask==3.0.3` 추가.
