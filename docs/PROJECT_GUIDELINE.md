# 금융 정보 분석 AI Agent — 프로젝트 가이드라인

## 0. 프로젝트 개요

국내 금융 시장(주식·채권·부동산·암호화폐)과 관련된 뉴스, 공시, 법·규제 변화를
자동으로 수집·분석하여 일별/주별/월별/연별 보고서를 생성하는 AI Agent를 구축한다.
개인 투자자와 금융 학습자가 시장 흐름과 규제 변화를 쉽게 파악할 수 있도록 돕는 것이
목표이며, **투자 자문이 아닌 정보 정리·학습 보조 도구**로 포지셔닝한다.

---

## 1. 프로젝트 범위 (Scope)

### 1-1. 타겟 독자
- 개인 투자자 (초~중급, 전문 트레이더 대상 아님)
- 금융/투자를 공부하는 학습자

→ 이에 따라 보고서 톤은 **전문 용어를 쓰되 짧은 설명을 곁들이는 수준**으로 설정한다.
너무 압축된 애널리스트 리포트체보다는, 맥락 설명이 포함된 형태가 적합하다.

### 1-2. 다루는 자산군
| 자산군 | 우선순위 | 비고 |
|---|---|---|
| 주식 | 1순위 | 국내 상장기업, 코스피/코스닥 |
| 채권 | 2순위 | 국고채 금리, 회사채 스프레드 등 거시 지표 위주 |
| 부동산 | 2순위 | 정책(대출규제, 세제), 실거래가 동향 위주 |
| 암호화폐 | 2순위 | 국내 거래소 상장/정책 이슈, 시세 자체보다 규제·이슈 중심 |

- **1순위(주식)**를 MVP 대상으로 먼저 구축하고, 나머지 자산군은 동일 파이프라인을
  확장 적용하는 방식으로 진행한다.
- 지역 범위는 **국내로 한정**한다 (해외 시장/기사는 추후 확장 과제로 분리).

### 1-3. 법·규제 정보의 범위
다음 3개 법령의 **개정 동향 및 관련 규제 변화**로 한정한다 (개별 소송/판례는 제외):
- 자본시장과 금융투자업에 관한 법률 (자본시장법)
- 은행법
- 금융소비자 보호에 관한 법률 (금융소비자보호법)

→ 국가법령정보센터 Open API, 금융위원회 보도자료를 주 소스로 사용한다.

### 1-4. 명시적으로 제외하는 것 (Out of Scope, 초기 단계)
- 해외 주식/글로벌 매크로 뉴스
- 실시간 시세·차트 기반 트레이딩 시그널
- 투자 종목 추천/매수·매도 권유
- 개별 판례, 소송, 징계 사례 분석
- 세무·상속 등 개인 재무 상담

## 2. 시스템 아키텍처

```
[데이터 수집] → [전처리/정제] → [저장(DB)] → [분석/키워드추출] → [보고서 생성] → [배포]
      ↑                                              ↑
   스케줄러(주기적 실행)                        LLM 기반 요약/분석
```

### 2-1. 데이터 수집 계층 (자산군별 소스 매핑)

| 자산군/영역 | 소스 | 방식 |
|---|---|---|
| 주식 | DART(전자공시시스템) | 공식 Open API |
| 주식 | 네이버 금융 뉴스, 언론사 RSS | RSS / 크롤링(약관 확인 필요) |
| 채권 | 한국은행 경제통계시스템(ECOS) | 공식 Open API |
| 부동산 | 국토부 실거래가 공개시스템 | 공식 Open API |
| 부동산 | 국토부/금융위 정책 보도자료 | RSS/크롤링 |
| 암호화폐 | 금융위/금감원 보도자료, 국내 거래소 공지 | RSS/크롤링 |
| 법·규제 | 국가법령정보센터 | 공식 Open API |
| 법·규제 | 금융위원회 보도자료 | RSS/크롤링 |

### 2-2. 전처리
- 중복 기사 제거 (제목/본문 유사도 기반)
- HTML 태그 제거, 텍스트 정규화, 한국어 형태소 분석
- 자산군 태깅(주식/채권/부동산/암호화폐/법규제), 날짜·출처 메타데이터 부여

### 2-3. 저장
- 초기: SQLite → 데이터 규모 커지면 PostgreSQL로 전환
- 스키마 예시: `articles(id, source, title, summary, url, published_at, asset_class, keywords)`

### 2-4. 키워드 추출 & 분석 (하이브리드 방식)
1. 1차 필터링: TF-IDF / KeyBERT로 후보 키워드 추출 (비용 저렴, 빠름)
2. 2차 정제: 상위 후보만 Claude API에 전달하여 문맥 기반 정리 및 트렌드 설명 생성
3. 숫자·법 조항 번호 등 **팩트성 정보는 원문에서 직접 추출한 값만 사용**
   (LLM 환각 방지를 위해 LLM은 요약/설명 역할에 한정)

### 2-5. 보고서 생성 주기별 구성
| 주기 | 구성 |
|---|---|
| 일별 | 자산군별 핵심 뉴스 3~5개, 당일 키워드 Top 10, 간단 코멘터리 |
| 주별 | 일별 데이터 집계, 주간 키워드 변화 추이 |
| 월별 | 자산군별 트렌드 그래프, 주요 법·정책 변화 타임라인 |
| 연별 | 연간 키워드 빈도 변화, 굵직한 규제 변화 총정리 |

### 2-6. 배포
- Markdown → HTML/PDF 변환 후 이메일 발송, 또는 간단한 웹 대시보드

## 3. 기술 스택 (초안)

| 영역 | 도구 |
|---|---|
| 언어 | Python |
| 스케줄링 | cron (초기) → Airflow (규모 확장 시) |
| LLM | Claude API |
| 키워드추출 | KeyBERT, konlpy |
| DB | SQLite → PostgreSQL |
| 보고서 출력 | Markdown → PDF/HTML |
| 배포 | 이메일 자동발송 / 웹 대시보드 |

## 4. 법적·윤리적 체크리스트

- [ ] 기사 원문 전문 재배포 금지 — 제목 + 요약 + 출처 링크 형태로만 저장
- [ ] 크롤링 대상 사이트의 `robots.txt` 및 이용약관 사전 확인
- [ ] 공식 Open API(DART, ECOS, 국가법령정보센터, 국토부) 우선 사용
- [ ] 보고서 하단에 "본 보고서는 정보 제공 목적이며 투자 권유가 아님" 면책 문구 명시
- [ ] 숫자·조항 등 팩트 정보는 반드시 원문 대조, LLM 생성값 그대로 사용 금지
- [ ] 특정 종목에 대한 매수/매도 권유성 표현 사용 금지

## 5. 단계별 로드맵 (MVP → 확장)

1. **1단계**: DART API로 국내 상장기업 공시 수집 → 규칙 기반 일별 요약 (LLM 미사용)
2. **2단계**: 주식 관련 뉴스 소스 1~2개 추가 + KeyBERT 키워드 추출
3. **3단계**: Claude API 연동 → 요약/트렌드 설명 고도화
4. **4단계**: 채권(ECOS)·부동산(실거래가)·암호화폐(공지) 소스로 자산군 확장
5. **5단계**: 법령정보센터 연동 → 법·규제 변화 트래킹 추가
6. **6단계**: 주간/월간/연간 집계 로직 + 트렌드 시각화
7. **7단계**: 자동 스케줄링 + 배포(이메일/대시보드)

---

## 6. 자체 평가 기준

- 추출된 키워드가 해당 기간의 실제 주요 이슈를 반영하는가
- 동일 이슈가 여러 소스에서 중복 집계되어 통계가 왜곡되지 않는가
- 보고서 내 사실 정보(수치, 법 조항 등)에 환각(hallucination)이 없는가
- 자산군 간 분량/비중이 지나치게 한쪽으로 쏠리지 않는가
